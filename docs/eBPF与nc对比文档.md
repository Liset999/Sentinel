## 1. 实验回顾：捕捉“幽灵短连接”
+ **实验对象**：目标端口 `8888`，连接方式 `nc -z`（极速扫描）。
+ **eBPF 表现**：精准捕捉到 `状态 2 (SYN_SENT)` 和 `状态 7 (CLOSE)`。
+ `**/proc/net/tcp**`** 表现**：即使每 0.1 秒采样一次，依然**颗粒无收**，完全没有看到任何连接记录。

## 2. 差异深度分析
### 2.1 看到的现象差异 (Observed Differences)
| **维度** | **/proc/net/tcp (传统方式)** | **eBPF (动态追踪)** |
| --- | --- | --- |
| **短连接捕捉** | **严重漏报**。无法发现存活时间低于采样间隔（如 1ms）的连接。 | **100% 捕获**。无论连接存活多短，只要触碰内核函数必被记录。 |
| **状态细节** | **静止快照**。只能看到连接在某一秒的静态状态。 | **全程录像**。能看到从握手到断开的完整生命周期（状态流转）。 |
| **异常检测** | **极难发现**。对于被内核瞬间 Reset 的非法连接完全无感。 | **秒级响应**。能实时发现内核丢弃或重置连接的底层行为。 |


### 2.2 统计口径差异 (Methodology Differences)
这是两者表现迥异的根本原因：

+ `**/proc/net/tcp**`** 是“拍照片” (Polling/Snapshot)**：
    - **机制**：用户态发起请求 -> 内核遍历整个 TCP 哈希表 -> 格式化为文本 -> 用户态读取。
    - **代价**：这是一种“拉取”模式。连接必须在拍照的那一瞬间恰好在表中，才会被看到。
+ **eBPF 是“安监控” (Event-Driven/Hooking)**：
    - **机制**：在内核函数 `tcp_set_state` 处设置探针。
    - **代价**：这是一种“推送”模式。内核每执行一次状态切换，就自动触发一次代码执行。只要发生，必有记录。

### 2.3 适用场景差异 (Scenario Differences)
+ `**/proc/net/tcp**`** 适用场景**：
    - **长连接巡检**：如数据库连接池、SSH 长会话。
    - **宏观指标**：大致了解当前服务器总连接数的量级（万级、十万级）。
+ **eBPF 适用场景**：
    - **微服务/RPC 诊断**：排查高频短连接下的偶发超时或 Connection Reset。
    - **网络延迟分析**：精确计算 TCP 三次握手或四次挥手各阶段的微秒级延迟。
    - **零侵入性能优化**：在不开启抓包（Tcpdump 太重）的前提下，实现全量连接的性能监控。

## 3. 核心避坑指南 (SRE 经验沉淀)
在本次实验中，我们还解决了一个极易被忽略的问题：**字节序 (Byte Order)**。

+ 内核字段 `skc_num`（源端口）使用**主机字节序**。
+ 内核字段 `skc_dport`（目的端口）使用**网络字节序**。
+ **结论**：在编写 eBPF 过滤条件时，必须意识到内存里的数字和我们看到的十进制数字可能是不一致的。
